## 2026-07-11 (Phase 1 Step 7 — My Bookings + self-serve cancellation) ✅

- `lib/cancellation.ts`: pure `evaluateCancellationPolicy(refundPolicy, startsAt)` — non-refundable offerings always blocked; inside `CANCELLATION_CUTOFF_HOURS` (48h) blocked with a policy message; otherwise allowed (member picks refund or credit). One function shared by the page's render-time estimate and the API route's authoritative check
- `POST /api/bookings/[id]/cancel`: confirmed-only; reads the booking scoped to the caller's account, evaluates policy, then **atomically claims** the status flip (`confirmed` → `refunded`/`credited`, guarded by `.eq("status","confirmed")` so a double-click or replay can only win once) *before* calling Stripe/inserting the credit — a failed refund or credit insert rolls the claim back to `confirmed` so the member can retry. Refund is a **partial refund on the booking's own `stripe_payment_intent_id`** (a multi-child booking shares one PaymentIntent across its Checkout session; each participant's booking refunds only its own `price_paid_pence` off that shared PI). Credit path inserts `mem_credits` (amount = price paid, `expires_at` = `CREDIT_EXPIRY_MONTHS` out). Reuses the Step 6 `sendBookingCancellationEmail` orchestrator (best-effort, never fails the request)
- `(member)/bookings` page: RLS-scoped read, split into Upcoming/Past by start time (not by status — a cancelled-but-future booking stays in Upcoming, badged). `BookingsList`/`BookingRow` client components (`components/bookings/`) hold local state like `HouseholdManager` does — cancel updates the row in place, no page reload. Blocked rows show the policy reason inline; eligible rows expand to a refund/credit choice. `MemberHeader` gained a "Bookings" nav link — `/bookings` was already in the middleware's guarded-route list from Step 2, no auth wiring needed
- **e2e 6/6** against a real dev server: seeded 4 confirmed bookings (non-refundable, <48h, ≥48h×2) for a test account, one with a **real test-mode Stripe PaymentIntent** (confirmed synchronously via the fixed test PaymentMethod `pm_card_visa`, no Elements/redirect needed) so the refund path exercises Stripe for real. Verified via DB: non-refundable and <48h bookings stayed `confirmed` untouched; credit booking → `credited` + correct `mem_credits` row (£7, expires 2027-07-11); refund booking → `refunded`. Verified via Stripe: the PaymentIntent's charge shows `refunded: true`, `amount_refunded: 700`. Verified via Gmail: both cancellation emails (credit and refund variants) delivered to `teams+memberscanceltest@empowrcic.org` with correct copy. Double-cancel on an already-settled booking → 409; no session → 401. All seeded rows + the auth user deleted after; DB verified zero leftover rows
- Gotcha (recurring): `with_server.py`'s `terminate()` doesn't reliably kill `npm run dev`'s child `node` process tree on Windows after a Playwright timeout — leaves a zombie holding port 3000 that silently no-ops the next `page.goto`.
