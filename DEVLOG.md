- **Netlify env push gotcha (new, worth keeping)**: the bulk `POST /accounts/{id}/env` 422s whenever a key already exists on the site (not just "5+ vars" as previously logged from Step 5 — it's any pre-existing key). The fix is **not** simply "push per-key" as Step 5's note implied — per-key POST still 422s on an existing key. The actual fix: `PATCH /accounts/{id}/env/{key}?site_id=...` with a **flat** body `{ "context": "...", "value": "..." }` (not the `{key, values:[...]}` shape POST wants). And **`context` can never be `"all"` on this PATCH** — Netlify rejects it with `"context can't be set to all"`; you must target a real context (`production`, `deploy-preview`, `branch-deploy`, `dev`). Targeting only `production` is actually the *better* outcome for a live-mode swap: previews/branch-deploys keep running on the old value (TEST keys, in this case) while only the real production site gets the new one — Netlify auto-splits the prior single `all` value into four explicit per-context values the first time you do this. Rebuild afterwards via `POST /sites/{id}/builds` (env var changes need a rebuild; this project's normal deploy path is git push, but a docs-only push doesn't rebuild automatically with new env values already sitting in Netlify — a direct build trigger was the right call here since there was no code change to push).
